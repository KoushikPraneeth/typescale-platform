# TypeScale v1.0.0 — release notes

TypeScale v1.0.0 is a local-first multiplayer typing-race platform with a GitOps-managed OrbStack Kubernetes runtime. The app image is immutable and promoted through review; Argo CD remains the workload reconciler.

## Release verification

- Application API reports version `1.0.0`; the local GitOps workload ran image digest `sha256:7e85ebde40f4797316bb381b52d371c7b800888ccda125b221cb41008e337cd6`.
- On OrbStack, 40 concurrent WebSocket clients completed a full race: 40/40 connections and completions, zero initial failures, zero unexpected post-join disconnects, peak 40 sockets. Matchmaking latency p50/p95/p99 was 3.971/19.275/91.158 ms. This is a local single-node synthetic run, not an SLO or cloud measurement; detailed results are in [`../benchmarks/local-websocket-races.md`](../benchmarks/local-websocket-races.md).
- The KEDA ScaledObject is Prometheus-backed with a 2–5 replica range. A separate 420-second held-WebSocket test previously verified 2→5 scale-out and return to 2; it is distinct from the completed-race latency run.
- Grafana's anonymous read-only API reported a healthy database, exposed the `TypeScale Overview` dashboard in search, and showed the Prometheus datasource. Prometheus targets for the TypeScale job were up during verification.
- App PR #12 passed application tests, container build/strict Trivy scan, and Helm validation; the main-branch image build passed and published the immutable digest. Platform chart and release validation are tracked by the release PR.

## Known limitations

- This project is a local portfolio/demo platform; it is not presented as production-ready.
- Active WebSockets do not survive termination of their owning pod in the tested port-forward path. See [`../benchmarks/pod-replacement-reliability.md`](../benchmarks/pod-replacement-reliability.md).
- Azure Container Apps did not autoscale in its WebSocket test. A separate, temporary Azure OIDC→ACR workflow proved keyless image publication only; the registry and identity were destroyed. No Azure cost-total or zero-cost claim is made.
- Local Redis and monitoring storage are ephemeral. KEDA scaling tests do not prove high availability or node-failure tolerance.
